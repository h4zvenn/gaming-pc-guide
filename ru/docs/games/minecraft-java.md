## Совместимость

- Перед установкой модов проверь правила сервера. Серверный античит может запрещать определённые клиентские моды.
- Используй версию загрузчика модов, соответствующую твоей версии Minecraft.
- Не смешивай моды Forge, Fabric и NeoForge в одном экземпляре.
- Не смешивай моды, созданные для разных версий Minecraft.
- Для шейдерпаков может требоваться конкретная версия Iris или OptiFine.
- Используй среду Java, поставляемую с лаунчером, если нет конкретной причины её менять.

Требования к версии Java для Minecraft со временем меняются. Перед сменой Java проверь официальные требования Minecraft для своей версии.

## Настройки графики

Начни с этих значений, затем меняй по одной настройке.

| Настройка | Рекомендуемый старт | Почему |
| --- | --- | --- |
| Render Distance | 12–16 чанков | Значительная стоимость по FPS, ОЗУ и загрузке чанков |
| Simulation Distance | Равна Render Distance или ниже | Снижает нагрузку на CPU от сущностей и тиков |
| Graphics | Fast | Повышает FPS при небольшой потере качества картинки |
| Smooth Lighting | Минимум | Снижает нагрузку на GPU |
| Clouds | Выключено или Fast | Экономит ресурсы GPU |
| Particles | Минимум | Снижает нагрузку на CPU и GPU |
| Entity Distance | 50–100% | Снижает нагрузку на отрисовку мобов и предметов |
| Biome Blend | Выключено или 3x3 | Снижает нагрузку на GPU на границах биомов |
| V-Sync | Выключено | Не добавляет задержку; VRR настраивай отдельно, если он поддерживается |
| Max Framerate | Частота обновления монитора или чуть ниже | Улучшает равномерность времени кадров |

Если FPS низкий, снижай настройки в таком порядке:

1. Render Distance
2. Simulation Distance
3. Particles
4. Entity Distance
5. Biome Blend
6. Smooth Lighting

## Ограничение FPS и задержка

Используй внутриигровой ползунок `Max Framerate` как основной ограничитель FPS.

Для мониторов с VRR:

- Включи G-SYNC или FreeSync в панели управления GPU и в OSD монитора.
- Держи внутриигровой V-Sync выключенным, если не нужно настраивать поведение VRR.
- Установи лимит FPS в пределах диапазона VRR, если подача кадров неравномерна.

В Minecraft Java нет встроенной поддержки NVIDIA Reflex или AMD Anti-Lag. Меньшая дальность прорисовки, меньше модов и стабильный FPS обычно важнее настроек, направленных только на задержку.

## Аргументы JVM

Не копируй из интернета наборы флагов JVM для «прироста FPS». Многие популярные наборы флагов рассчитаны на серверы Minecraft, а не на клиенты.

Начни с аргументов Java по умолчанию из твоего лаунчера. Меняй их, только если есть конкретная проблема, например фризы из-за сборки мусора.

Если ты настраиваешь память вручную:

- Не выделяй Minecraft всю ОЗУ системы.
- Оставь достаточно памяти для Windows, драйвера GPU, браузера и других приложений.
- Типичная отправная точка — 4–8 ГБ для Minecraft в зависимости от общего объёма ОЗУ и размера сборки модов.
- Устанавливай `-Xms` и `-Xmx` равными только после тестирования: это может уменьшить изменение размера кучи, но не гарантирует лучшую производительность.

Пример отправной точки для экземпляра с модами при достаточном объёме ОЗУ:

```text
-Xms4G -Xmx4G
```

Проверяй по одному изменению JVM. Если после смены аргументов Java появились фризы, вернись к значениям лаунчера по умолчанию.

## Моды

Проверяй в таком порядке:

1. Базовый уровень на ванильном Minecraft.
2. Моды для производительности по одному.
3. Шейдерпаки — только после стабилизации базового экземпляра.
4. Контентные моды — после проверки производительности.

Не устанавливай большую сборку модов и моды для производительности одновременно без тестирования. Если появилась проблема, сначала удали последний добавленный мод.

## Частые проблемы

| Симптом | Первая проверка |
| --- | --- |
| Низкий FPS при высокой загрузке CPU | Снизь Render Distance и Simulation Distance |
| Фризы каждые несколько секунд | Проверь выделение ОЗУ, версию Java и поведение сборки мусора |
| Фризы при входе в новые области | Снизь Render Distance, используй SSD или предварительно сгенерируй чанки |
| Задержка компиляции шейдеров | Дай шейдерам скомпилироваться; обнови Iris или OptiFine, если это совместимо |
| Сбой из-за мода | Проверь версии Minecraft, загрузчика модов и модов |
| Ошибка нехватки памяти | Увеличивай выделенную ОЗУ, только если в системе достаточно свободной памяти |

## Сценарий бенчмарка

Используй один и тот же мир, seed, координаты, время, погоду и настройки для каждого прогона.

| Параметр | Рекомендация |
| --- | --- |
| Мир | Фиксированный seed и фиксированные координаты |
| Время | Фиксированное командой `/time set 6000` |
| Погода | Ясная |
| Прогрев | 5 минут |
| Прогоны | Не менее 3 |
| Метрики | Средний FPS, 1% минимумов, 0,1% минимумов, время кадров, использование ОЗУ |
| Тестирование модов | Сначала ванильная база, затем по одному моду |

Полный протокол см. в [шаблонах бенчмарка](../16-benchmark-templates.html).

---

## Проверка

Запиши версию Minecraft, загрузчик модов, список модов, среду Java и дату теста. Сравни один и тот же мир, seed, координаты, время, погоду, дальность прорисовки и настройки шейдеров минимум для трёх прогонов. Проверяй время кадров и использование памяти, а не только FPS.

Сначала используй ванильную базу и проверь правила сервера перед тестированием клиентских модов.

## Откат

1. Восстанови `options.txt` из резервной копии.
2. Верни аргументы JVM к значениям лаунчера по умолчанию.
3. Удаляй моды или шейдерпаки по одному.
4. Повтори сценарий бенчмарка.
