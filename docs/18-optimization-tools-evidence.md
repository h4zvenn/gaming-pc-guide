# 18. Third-Party Optimization Tools: Evidence

> A third-party tool can publish a claim, publish documentation, and publish code. Independent testing confirms the effect. The guide needs all three layers before citing an FPS or latency number.

## 1. How to read the tool entries

| Layer | Question |
|---|---|
| Claimed by developer | What does the tool advertise? |
| Confirmed by docs or code | What does official documentation or source code show? |
| Confirmed by test | What did independent measurement show? |

## 2. What the evidence review found

- Commercial boosters: FPS gain claims could not be confirmed independently. Official documentation stated that results depend on hardware, drivers, game settings and what limits performance. Rollback paths were documented.

- Open-source tweak tools: documentation and code were available. Automated tests for tuning logic were mostly absent. Service, registry and debloat surfaces were safety-relevant.

## 3. Gap summary

- Independent test evidence for closed-source commercial boosters is missing.

- Open-source tweak tools lack automated tests for tuning logic.

## 4. How to use

- Treat third-party tools as proposed optimizations.

- Apply the same standard: claim, docs/code, test, license, safety, rollback.

- Do not cite a tool number without the corresponding evidence layer.
